Color themes

- Seven new color themes join Querithm Dark and Querithm Light:
  - Dark: Cortado, Fathom, Inkwell, Damson and Juniper.
  - Light: Floe and Vellum.

  Each has its own look, and a short line in Settings says when it suits, for example evenings, bright offices, or eyes
  that tire easily. Pick one in Settings › Appearance › Color theme.
- "Match system" now uses a dark theme and a light theme of your choice, and switches between them when your computer
  does.
- Querithm Dark and Querithm Light look the same as before.

Syntax colors

- **Syntax colors now follow your color theme.** The new choice, Default, is now the default. Each color theme brings its
  own SQL colors.
- On Querithm Dark and Light you keep the colors you know. TRUE / FALSE / NULL, AND / OR / NOT, CTE names and schema names
  now get colors of their own.
- To keep the previous colors on every theme, choose Standard in Settings › Appearance › Syntax colors. A note with a
  "Use Standard" button appears once after the update.
- If you had picked Color-blind safe, Neon, Forest, Ember or Ocean, you keep it. The only change there is the variable
  fix below.
- New setting: Italic comments. Turn it off if slanted text is harder to read.

Editor and toolbar

- **Duplicate line:** press `Ctrl+D` (or `Cmd+D` on macOS) in the editor to duplicate the current line or selection.
- **Toggle line comment button:** a new `//` button in the top bar comments or uncomments the current line or selection
  (`Ctrl+/` or `Cmd+/`).
- **Drag and drop text:** dragging a table, column or text snippet into the editor now inserts the exact text cleanly
  where you drop it, without stray `$0` markers or escaped `$` signs.
- **Cleaner snippet placeholders:** snippet tabstops use a subtler highlight and no longer leave a stray cursor bar at the
  end.
- Typing inside large PostgreSQL, Oracle or MySQL scripts with an unclosed `$$` block stays fast instead of slowing down
  on every keystroke.

Suggestion list

- Tables, views and functions now show their name once. The right side shows the schema, then the number of columns
  and rows, for example `sales · 42 cols · ~12k rows`. Before, the right side repeated the full name.
- Every row now shows its schema, also `dbo` on SQL Server, `public` on PostgreSQL and `main` on SQLite and DuckDB.
  Before, those rows had no schema, so the list looked mixed.
- Views, procedures and functions say what they are on the right. Tables show the table icon only.
- After you type a schema and a dot, such as `sales.`, the right side no longer repeats the schema.
- What Enter inserts has not changed.
- On a test database with 10,000 tables, building the list after FROM now takes about 45 ms instead of about 135 ms.

Object Explorer and tabs

- **Custom connection order:** drag and drop connections and groups in the Object Explorer to arrange them in the order
  you prefer (replacing pinning). The same order is used in the Connect dialog.
- Moving a query tab into a split or another tab group now preserves its width cleanly instead of overflowing onto
  neighbouring tabs.
- Right-click context menus now close reliably when you click outside them (including on the tree or tab they opened
  from), and pressing Escape inside a submenu closes only the submenu.
- With no query tab open, the Reveal button next to the Object Explorer search box now reveals that database in the tree.

Easier to read and refreshed look

- Updated Querithm app icon, start screen animation and Windows / macOS installer visuals.
- Search matches in the editor are now readable on every theme. Before, the current match hid the text under it.
- Error, warning and info underlines use your theme's colors. Warnings are easier to see on light themes and easier to
  tell apart from errors.
- Messages and notices now show an icon (error, warning, success, info), so you can tell their kind without relying on
  color.
- Buttons show when you press them, and a disabled button now looks plainly unavailable.
- When you move with the Tab key, the focus ring on top bar buttons, main buttons and switches is now a clear 2 px ring
  around the control.
- Notifications no longer let the grid or the editor show through behind their text.

Production safety and reliability

- Stronger production checks across all six engines: catches destructive statements hidden behind MySQL `DELIMITER` or
  `sql_mode` changes, PostgreSQL `standard_conforming_strings` changes and `DO` blocks, SQL Server `sp_executesql`,
  `xp_cmdshell`, `OPENQUERY` and `RESTORE`, and Oracle dynamic SQL packages.
- Estimated plans on MySQL and PostgreSQL now refuse scripts whose statement boundaries depend on session settings,
  preventing hidden statements from running when asking for a plan.
- Passwords written as bare or bracketed names in SQL Server scripts are now masked in query history.
- Schema changes refresh metadata more reliably across every engine (including MySQL and Oracle DDL updating right away
  without waiting for a commit, and deferred refreshes inside transactions no longer getting lost).
- Deeply nested SQL comments and very large scripts no longer crash the engine or formatter.
- Updated a built-in component (`cookie` 0.18.3) to address security advisory `RUSTSEC-2026-0594`.

Fixes

- With two Querithm windows open, changing a setting in one no longer undoes a setting you changed in the other, even
  when both save at the same moment.
- A setting you change while an earlier change is still being saved is no longer lost, and closing Querithm waits for a
  save that has already started.
- If the background service stops answering while saving settings, Querithm now shows "Settings could not be saved" after
  about 35 seconds instead of staying stuck on "Saving…".
- SQL Server: a function in the `dbo` schema now shows once in the suggestion list instead of twice.
- SQL Server and MySQL: variables such as `@id` now show in the variable color in every syntax color choice, and system
  variables such as `@@ROWCOUNT` are colored as one word.
