Color themes

- Seven new color themes join Querithm Dark and Querithm Light:
  - Dark: Cortado, Fathom, Inkwell, Damson and Juniper.
  - Light: Floe and Vellum.

  Each has its own look, and a short line in Settings says when it suits, for example evenings, bright offices, or eyes
  that tire easily. Pick one in Settings › Appearance › Color theme.
- "Match system" now uses a dark theme and a light theme of your choice, and switches between them when your computer
  does.
- Querithm Dark and Querithm Light look the same as before.

Syntax colors

- **Syntax colors now follow your color theme.** The new choice, Default, is now the default. Each color theme brings its
  own SQL colors.
- On Querithm Dark and Light you keep the colors you know. TRUE / FALSE / NULL, AND / OR / NOT, CTE names and schema names
  now get colors of their own.
- To keep the previous colors on every theme, choose Standard in Settings › Appearance › Syntax colors. A note with a
  "Use Standard" button appears once after the update.
- If you had picked Color-blind safe, Neon, Forest, Ember or Ocean, you keep it. The only change there is the variable
  fix below.
- New setting: Italic comments. Turn it off if slanted text is harder to read.

Easier to read

- Search matches in the editor are now readable on every theme. Before, the current match hid the text under it.
- Error, warning and info underlines use your theme's colors. Warnings are easier to see on light themes and easier to
  tell apart from errors.
- Messages and notices now show an icon (error, warning, success, info), so you can tell their kind without relying on
  color.
- Buttons show when you press them, and a disabled button now looks plainly unavailable.
- When you move with the Tab key, the focus ring on top bar buttons, main buttons and switches is now a clear 2 px ring
  around the control. Before, it was a thin line inside it.
- Notifications no longer let the grid or the editor show through behind their text.

Suggestion list

- Tables, views and functions now show their name once. The right side shows the schema, then the number of columns
  and rows, for example `sales · 42 cols · ~12k rows`. Before, the right side repeated the full name.
- Every row now shows its schema, also `dbo` on SQL Server, `public` on PostgreSQL and `main` on SQLite and DuckDB.
  Before, those rows had no schema, so the list looked mixed.
- Views, procedures and functions say what they are on the right. Tables show the table icon only.
- After you type a schema and a dot, such as `sales.`, the right side no longer repeats the schema.
- What Enter inserts has not changed.
- On a test database with 10,000 tables, building the list after FROM now takes about 45 ms instead of about 135 ms.

Fixes

- With two Querithm windows open, changing a setting in one no longer undoes a setting you changed in the other, even
  when both save at the same moment.
- A setting you change while an earlier change is still being saved is no longer lost. Closing Querithm now waits for a
  save that has already started.
- If the background service stops answering while Querithm saves your settings, you now see "Settings could not be
  saved" after about 35 seconds, and your next change tries again. Before, Settings kept showing "Saving…" with no
  message.
- Object Explorer: with no query tab open, the Reveal button next to the search box now shows that database in the tree.
  Before, it did nothing.
- SQL Server: a function in the dbo schema now shows once in the suggestion list. Before, it could show twice, as
  `fnName` and as `dbo.fnName`.
- SQL Server and MySQL: variables such as `@id` now show in the variable color, in every syntax color choice. Before,
  they showed in the function color. System variables such as `@@ROWCOUNT` are now colored as one word.
